# Ассистент для разбора ИБ-алертов

Ассистент разбирает события входа в аккаунт, фишинговые письма и срабатывания антивируса. Он выделяет факты из сообщения, определяет срочность и предлагает следующую проверку. Результат можно использовать для сортировки алертов перед ручным разбором.

## Вход и выход

На вход поступает текст одного алерта или фрагмент журнала. На выходе получается JSON с типом события (`event_type`), приоритетом (`priority`), цитатами из алерта (`evidence`) и следующей проверкой (`next_check`).

Например, для алерта «Для user01 зафиксировано 5 неудачных попыток входа. Затем выполнен успешный вход в тот же аккаунт с нового IP» результат может выглядеть так.

```json
{
  "event_type": "suspicious_login",
  "priority": "medium",
  "evidence": [
    "Для user01 зафиксировано 5 неудачных попыток входа",
    "Затем выполнен успешный вход в тот же аккаунт с нового IP"
  ],
  "next_check": "Уточнить у владельца аккаунта, выполнял ли он этот вход."
}
```

## Обработка

1. Модель выделяет факты о событии и дословные фрагменты алерта, которые их подтверждают.
2. По этим фактам модель определяет тип события, приоритет и следующую проверку.

Для событий входа используются типы `suspicious_login` и `failed_attempts`, для писем и файлов - `phishing` и `malware`. Подтверждённая обычная активность получает тип `expected_activity` и приоритет `low`. При нехватке сведений возвращаются `insufficient_data` и `unknown`.

В учебных правилах `high` назначается, когда владелец отрицает успешный вход, получатель ввёл данные на фишинговой странице или подтверждён запуск вредоносного файла. `medium` используется для подозрительного входа без объяснения, серии от трёх неудачных попыток, фишингового письма без подтверждённого ввода данных или обнаруженного вредоносного файла без подтверждённого запуска.

В One-shot обе операции выполняются за один запрос. В режиме Sequential первый запрос извлекает цитаты, скрипт сверяет их с алертом и передаёт второму запросу в JSON. Оценка зависит от извлечённых фактов, поэтому запросы идут по порядку. Скрипт объединяет цитаты и оценку в тот же итоговый JSON, что и в One-shot. Оба режима используют `nvidia/nemotron-3.5-super-vl:free` через OpenRouter.

## Запуск

Нужен Python 3.9 или новее. Ключ OpenRouter задаётся в поле `OPENROUTER_API_KEY` файла `.env`. Сторонних зависимостей пока нет, поэтому `requirements.txt` пуст.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py "Для user01 зафиксировано 5 неудачных попыток входа. Затем выполнен успешный вход в тот же аккаунт с нового IP"
.\.venv\Scripts\python.exe main.py --workflow "Для user01 зафиксировано 5 неудачных попыток входа. Затем выполнен успешный вход в тот же аккаунт с нового IP"
```

Скрипт проверяет структуру JSON, соответствие приоритета типу события и наличие цитат в исходном алерте. При ошибке печатает сообщение и завершает работу с кодом 1. В Sequential в сообщении указан этап ошибки.

## Сравнение режимов

`evaluate.py` запускает оба режима на 10 синтетических алертах с заранее заданными типами и приоритетами. Среди неоднозначных случаев есть вход через корпоративный VPN после серии ошибок, учебное фишинговое письмо и алерт о файле без вердикта антивируса.

```powershell
.\.venv\Scripts\python.exe evaluate.py
```

Успешным считается запуск с валидным итоговым JSON. Точность считается по совпадению типа события и приоритета с эталоном. Ошибка выполнения считается неверным ответом. Скрипт измеряет время обработки и считает фактические запросы. Токены суммируются по полю `usage.total_tokens`, а в среднее входят запуски с известным расходом.

| Метрика | One-shot | Sequential |
|---|---:|---:|
| Доля успешных выполнений | 100% | 90% |
| Точность типа и приоритета | 90% | 90% |
| Среднее время, с | 10,071 | 2,114 |
| Среднее число вызовов | 1,0 | 1,9 |
| Средний расход токенов | 631,8 | 687,0 |
